# Reliability audit: watch ↔ phone (October 2026)

Method: read every sync path (`shared/…/sync`, `…/link`, `…/settings`, `…/core/ledger`, `…/core/headphones`), both apps'
Data Layer services, workers, receivers and manifests, then wrote JVM tests with a fake Data Layer for each suspicion.
Severity: **crash** · **data loss** · **disconnection** (a link or a change that silently does not happen) · **cosmetic**.
File:line references are to the code *after* the fixes (the old line is described). Nothing was run on a watch or a phone.

## Checked and found sound (with the evidence)

- **History sync is idempotent and order-proof.** A day is replaced whole in one transaction (`PhoneDb.replaceDay`), keyed by a CRC digest, so repeating, interrupting or running it twice cannot double a minute (`HistorySyncTest`, `SyncCompatibilityTest`: interrupted, repeated, minute landing mid-fetch → self-heals next sync). Parts that shift while being fetched are de-duplicated (`distinctBy`).
- **Merge rule for the same minute from two devices:** one record per minute, the louder, never the sum (`mergeByMinute`); a headphone minute that wins removes the ambient one, a room that wins drops the phone minute (`resolvePhoneMinute`). Daily dose is the ambient ledger's only.
- **Headphone state ordering:** `sequence = max(prev + 1, now)` persisted (`PhonePrefs.nextSequence`), the watch drops anything not newer (`ExposureRepository.onPhoneListening`); a reinstall cannot go backwards unless the clock does.
- **Sizes:** DataItems < 3 KB, ledger parts ≤ 90 KB asserted for a full window (33 days × both ledgers × both origins × 1440 min). Assets/ChannelClient unnecessary.
- **Capabilities:** names in both `wear.xml` match the manifest `CAPABILITY_CHANGED` filters (`/voxara_watch_app`, `/voxara_phone_app`); `FILTER_REACHABLE` everywhere. Phone app absent: the watch is standalone and only the link chip changes. Phone out of range: pull-based sync simply resumes.
- **Foreground services:** watch `microphone` is started only from a visible surface; on refusal it stops itself and the watchdog/boot path posts a tap-to-resume notification (`DosimeterService.kt:298–330`, `BootReceiver.kt`, `MonitoringWatchdogWorker.kt`). Phone `connectedDevice` declares `FOREGROUND_SERVICE_CONNECTED_DEVICE` and the `CHANGE_NETWORK_STATE` prerequisite; refusal falls back to a one-shot sample. `POST_NOTIFICATIONS` is asked in context on the phone.
- **Boot:** the watch posts a prompt only; the phone restarts its headphone watcher at boot/update (`connectedDevice` is not on the types Android blocks at boot). `SyncWorker` (WorkManager) survives reboot.
- **Threading:** SQLite helpers are singletons using `applicationContext`, writes are transactional; listener services run on a background thread (`runBlocking` there is fine). Scopes in services are cancelled in `onDestroy`; `HeadphoneWatcher` unregisters all four callbacks in `stop()`. ViewModel holds the application context only.
- **Headphone report latency:** the watch never stops measuring or alerting while it waits for the phone (`ListeningLayerSafetyTest` passes untouched); an older phone app's 16-minute report path still exists for compatibility.

## Follow-up during the phone redesign: "Got it" is idempotent

With the alert history written off the main thread (S3), a "Got it" / "Snooze" / "Dismiss" tapped before its history row was written would find no row to mark and be lost. `AlertHistoryWriter.resolve` now queues the acknowledgement on the same single thread, behind the row it acknowledges; the notification actions (`AlertActionReceiver`) and the headphone-panel dismiss (`MainActivity`) go through `AlertNotifier.historyWriter`, and the receiver finishes its broadcast after the write (`onDone`). A second tap finds nothing unresolved and changes nothing. Tests: `AlertHistoryWriterTest` ("a Got it that lands before the row is written is not lost", "acknowledging twice changes nothing", "resolve reports completion even when the log fails"). Residual: none known; a process kill between the tap and the write loses it, as for any queued write.
